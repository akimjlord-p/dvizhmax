# ДвижМАКС — бот для хакатона MAX

Бот в MAX помогает выбрать событие в Москве и найти людей, которые тоже собираются
на него пойти. События приходят из KudaGo, размечаются YandexGPT и подбираются по
интересам. Если два человека хотят пойти вместе, бот сообщает о мэтче и помогает
добровольно обменяться контактом.

Бот: [@t110_hakaton_max_bot](https://max.ru/t110_hakaton_max_bot)

## Возможности

- Онбординг: согласие на обработку данных → Москва → анкета 18+ или гостевой режим «Только афиша».
- Анкета: имя, пол, возраст, описание и фото (необязательны), минимум 3 интереса; редактирование любого поля.
- Афиша: одна карточка события за раз с фото, датой ближайшего сеанса или периодом, адресом и ценой.
  После «👍 Нравится» или «Не моё» карточка помечается реакцией и приходит следующая.
- «Хочу пойти» добавляет событие в «Мои планы» и предлагает найти компанию.
- Поиск компании: анкеты людей с активным планом на то же событие и их общие с тобой интересы; «👍 Пойти вместе» — это лайк.
- Входящие лайки: раз в минуту приходит уведомление «с тобой хотят пойти N человек» с кнопкой «Посмотреть анкеты».
- Мэтч: оба получают сообщение и кнопку «Поделиться контактом». Контакт отправляется встроенной кнопкой
  MAX или текстом и доходит до второго человека только после подтверждения.
- Каталог обновляется каждые 12 часов; пропавшие из KudaGo события помечаются и затем скрываются.

| Команда | Раздел |
| --- | --- |
| `/start` | Онбординг или текущий шаг |
| `/feed` | Афиша |
| `/liked` | Понравившиеся |
| `/plans` | Мои планы и поиск компании |
| `/profile` | Анкета |
| `/demo` | Демо-сценарий до мэтча |

## Развёртывание

Всё работает в Docker: PostgreSQL, Redis, миграции, бот и catalog-worker. Бот, миграции,
worker и служебные команды запускаются из **одного образа** `dvizhmax-app`, поэтому
`docker compose up -d --build` одной командой собирает его, применяет миграции и
перезапускает бота и worker.

Есть три варианта — они различаются только тем, как MAX доставляет сообщения боту:

| Вариант | Когда подходит | Команда запуска |
| --- | --- | --- |
| **A. Long polling** | Локально или на сервере без домена | `docker compose -f docker-compose.yml -f docker-compose.polling.yml up -d --build` |
| **B. Webhook + Caddy** | Сервер с доменом, порты 80 и 443 свободны | `docker compose -f docker-compose.yml -f docker-compose.webhook.yml up -d --build` |
| **C. Webhook + nginx на хосте** | На сервере уже есть nginx (так работает наш прод) | `docker compose up -d --build` |

Все три варианта проверены 2026-09-25 на Ubuntu x86_64 с Docker Compose v5: образ
собирается с нуля примерно за 40 секунд, миграции доходят до `0007_match_contacts`,
бот запускается от непривилегированного пользователя `app`.

### Шаг 1. Подготовка (для всех вариантов)

1. Установить [Docker Engine](https://docs.docker.com/engine/install/) и Docker Compose v2.24 или новее.
2. Скачать код и создать `.env` из шаблона:

   ```bash
   git clone https://github.com/akimjlord-p/dvizhmax.git
   cd dvizhmax
   cp .env.example .env
   ```

3. Заполнить в `.env` обязательные значения (полный список — в разделе [Конфигурация](#конфигурация)):

   | Переменная | Что указать |
   | --- | --- |
   | `POSTGRES_PASSWORD` | Любой длинный пароль |
   | `DATABASE_URL` | `postgresql+psycopg://dvizhmax:ТОТ_ЖЕ_ПАРОЛЬ@postgres:5432/dvizhmax` |
   | `MAX_BOT_TOKEN` | Токен бота из кабинета MAX для партнёров |
   | `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | Ключ Yandex AI Studio; без него события не размечаются и не попадают в ленту |
   | `MAX_WEBHOOK_SECRET` | Для вариантов B и C: 5–256 символов, латиница, цифры, `-`, `_` |

### Шаг 2A. Long polling

Самый простой вариант: не нужны домен, сертификат и открытые порты.

```bash
docker compose -f docker-compose.yml -f docker-compose.polling.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.polling.yml logs -f bot
```

В логе должно появиться `Бот: @имя_бота` и `Зарегистрировано 11 обработчиков событий`.
Напишите боту `/start` — ответ придёт сразу.

> MAX не отдаёт сообщения через long polling, пока у бота настроен webhook. Для локальной
> разработки используйте отдельного тестового бота. Если запустить polling с токеном
> боевого бота, в логе будет `БОТ ИГНОРИРУЕТ POLLING! Обнаружены установленные подписки`.

### Шаг 2B. Webhook + Caddy (всё в Docker)

Нужны домен с A-записью на IP сервера и свободные порты 80 и 443. HTTPS-сертификат
Caddy получает и продлевает сам.

1. Дописать домен в `.env`:

   ```env
   DOMAIN=bot.example.com
   ```

   Адрес webhook (`https://DOMAIN/max/webhook`) собирается автоматически, `MAX_WEBHOOK_URL` задавать не нужно.

2. Запустить:

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.webhook.yml up -d --build
   ```

3. Проверить, что запросы доходят до бота:

   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" -X POST https://bot.example.com/max/webhook
   ```

   Ожидаемый ответ — `403`: бот отклоняет запрос без секрета, значит, Caddy до него проксирует.
   При старте бот сам подписывается на webhook в MAX. Конфиг прокси — `deploy/caddy/Caddyfile`.

Чтобы не писать `-f` в каждой команде: `alias dc='docker compose -f docker-compose.yml -f docker-compose.webhook.yml'`.

### Шаг 2C. Webhook + nginx на хосте

Бот слушает только `127.0.0.1:8080`, nginx сервера проксирует на него `/max/webhook`.

1. Дописать в `.env`:

   ```env
   MAX_TRANSPORT=webhook
   MAX_WEBHOOK_URL=https://bot.example.com/max/webhook
   ```

2. Подключить сайт в nginx и получить сертификат:

   ```bash
   sudo cp deploy/host-nginx/dvizhmax.conf /etc/nginx/sites-available/dvizhmax.conf
   sudo sed -i 's/bot.example.com/ВАШ_ДОМЕН/g' /etc/nginx/sites-available/dvizhmax.conf
   sudo ln -s /etc/nginx/sites-available/dvizhmax.conf /etc/nginx/sites-enabled/
   sudo nginx -t && sudo systemctl reload nginx
   sudo certbot --nginx -d ВАШ_ДОМЕН
   ```

   Если у домена уже есть сайт, достаточно добавить в него блок `location = /max/webhook`
   из `deploy/host-nginx/dvizhmax.conf`.

3. Запустить:

   ```bash
   docker compose up -d --build
   ```

### Шаг 3. Демо-данные

После старта catalog-worker сразу начинает импорт афиши, он занимает несколько минут.
Когда он закончится, создайте демо-событие и демо-анкеты:

```bash
docker compose --profile tools run --rm demo-seed
```

### Управление

Команды показаны для варианта C. Для A и B добавьте те же `-f`, что при запуске.

```bash
docker compose ps                                        # статус контейнеров
docker compose logs -f bot                               # логи бота
docker compose restart bot                               # перезапуск бота
docker compose down                                      # остановка; данные остаются в томах
docker compose --profile tools run --rm demo-reset       # сбросить лайки, мэтчи и контакты на демо-событии
docker compose --profile tools run --rm profile-reset    # удалить все реальные профили
```

Обновление до новой версии кода:

```bash
git pull --ff-only
docker compose up -d --build
```

Команда пересобирает образ, применяет новые миграции (сервис `migrate` отрабатывает до
запуска бота) и пересоздаёт бота и worker. PostgreSQL и Redis не перезапускаются.

### Если что-то не работает

| Симптом | Причина и решение |
| --- | --- |
| Long polling: бот молчит, в логе `БОТ ИГНОРИРУЕТ POLLING` | У бота настроен webhook — нужен отдельный тестовый бот |
| Webhook: `/max/webhook` отвечает 502 | Бот не запущен или слушает другой порт (`MAX_WEBHOOK_PORT`); смотреть `logs bot` |
| Webhook: `/max/webhook` отвечает 404 | Путь в прокси не совпадает с `MAX_WEBHOOK_PATH` |
| Caddy не получил сертификат | A-запись домена не указывает на сервер или закрыты порты 80/443; смотреть `logs caddy` |
| `No such image: dvizhmax-app` | Служебная команда запущена до первой сборки — сначала `up -d --build` |
| Лента пустая | Афиша ещё импортируется или не заданы ключи Yandex |

## Сценарий проверки

Нужны два аккаунта MAX (A и B). Проверка работает в web и в мобильном MAX.

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | A: `/start` | Объяснение данных и кнопки «Согласен» / «Не согласен». «Не согласен» → кнопка «Вернуться к согласию». |
| 2 | «Согласен» → «Продолжить с Москвой» | Выбор: «Создать профиль» или «Только афиша». Любой текст вместо кнопки повторяет вопрос. |
| 3 | «Создать профиль», заполнить анкету | Возраст меньше 18 не принимается. «Продолжить» появляется после 3 интересов. |
| 4 | «Афиша», нажать «👍 Нравится» | На карточке появляется «✅ Нравится», кнопки реакции исчезают, приходит следующая карточка. |
| 5 | На карточке нажать «Хочу пойти» → «Найти компанию» | Событие в «Мои планы»; показываются анкеты людей, идущих на него, или «Других анкет пока нет». |
| 6 | B: то же событие → «Найти компанию» → «👍 Пойти вместе» на анкете A | На анкете: «Лайк отправлен. Если интерес будет взаимным — сообщим о мэтче». A в течение минуты получает уведомление с кнопкой «Посмотреть анкеты». |
| 7 | A: «Посмотреть анкеты» → «👍 Пойти вместе» | Оба получают «Есть мэтч 🎉» с кнопками «Поделиться контактом» / «Пока не сейчас» и меню. |
| 8 | A: «Поделиться контактом» → «📱 Отправить мой контакт» → «Да, отправить» | B получает контакт A (карточка MAX и текст) и кнопку «Поделиться своим контактом». |
| 9 | Написать произвольный текст | «Сейчас здесь нужно выбрать действие кнопкой ниже» и меню. |

Быстрый путь с одним аккаунтом: заполнить анкету → `/demo` → «Хочу пойти» →
«Найти компанию» → «👍 Пойти вместе» на демо-анкете → мгновенный мэтч → «Поделиться контактом».

## Тестовые данные

- **Демо-анкеты «Демо Катя», «Демо Саша», «Демо Лёша» синтетические.** У них фиктивные MAX ID
  `9000000001–9000000003`, описание «Тестовая анкета для демонстрации мэтча» и фото
  из `assets/images`. Они заранее «лайкают» пользователя, поэтому мэтч с ними наступает сразу.
  Демо-анкеты не получают сообщений; контакт, отправленный демо-анкете, никуда не уходит.
- **«Демо-встреча ДвижМАКС»** — фиксированное событие через 7 дней от запуска `demo-seed` или `demo-reset`.
- **`DEMO_TEAM_MAX_USER_IDS`** — реальные анкеты команды, которые добавляются в демо-событие как
  обычные кандидаты. Лайки и контакты между ними и тестировщиками настоящие.
- События афиши — реальные данные KudaGo.

## Рекомендации

Каждый выбранный интерес даёт тегу стартовый вес 1.0. Реакции меняют вес тегов события:
«Нравится» +0.1, «Не моё» 0, «Хочу пойти» +0.5 в сумме с лайком. Отмена лайка и похода
возвращает вклад. Оценка карточки — сумма весов её тегов: первичные с множителем 1.0,
вторичные 0.4. Три карточки подряд с одним первичным тегом не показываются, каждая четвёртая
карточка случайная. Оценённые события в ленту не возвращаются; показанные без реакции
исключаются на 24 часа.

## Архитектура

```text
bot/                     Хендлеры MAX: онбординг, лента, поиск компании, контакты, уведомления
integrations/            Клиенты KudaGo и Yandex AI Studio
infrastructure/db/       Модели SQLAlchemy, репозитории, миграции Alembic
infrastructure/cache/    Очередь карточек ленты (Redis или память процесса)
workers/                 Импорт каталога, демо-данные, сброс демо и профилей
tests/                   Юнит- и интеграционные тесты
docs/                    Схема данных, пользовательский путь, обновление каталога
deploy/                  Конфиги Caddy и nginx для webhook
Dockerfile               Единый образ для бота, миграций, worker и служебных команд
docker-compose*.yml      Базовый стек и режимы long polling / webhook + Caddy
```

Бот и catalog-worker — отдельные процессы, общаются через PostgreSQL. Схема данных —
[docs/data_model.md](docs/data_model.md), путь пользователя — [docs/user_flow.md](docs/user_flow.md),
импорт — [docs/catalog_update.md](docs/catalog_update.md).

Шаблон: [`.env.example`](.env.example). Бот и worker читают `.env` при запуске.

| --- | --- |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL для docker compose |

## Разработка

Зависимости зафиксированы: прямые — в `requirements.txt`, все транзитивные — в `constraints.txt`
(снимок рабочего образа).

```bash
pip install -r requirements.txt -c constraints.txt
python -m unittest discover -s tests -v
```

Интеграционные тесты запускаются, если задан `TEST_DATABASE_URL` с отдельной базой,
имя которой заканчивается на `_test`. Миграции: `python -m alembic upgrade head`.

## Персональные данные

Бот хранит MAX ID, город, интересы, реакции и планы. С анкетой — также имя, пол, возраст,
описание и фото. Поиск компании доступен только с 18 лет. Контакт сохраняется, только если
пользователь сам отправил его после мэтча, и передаётся только второму участнику мэтча
после подтверждения.

## Известные ограничения

- Только Москва; источник событий — только KudaGo.
- Ссылка `max://user/<id>` на профиль в MAX не открывается, поэтому связь после мэтча — через добровольный обмен контактом.
- Нет модерации анкет и фото, жалоб и блокировки из интерфейса (таблица `user_blocks` есть).
- Нет общего чата после мэтча.
- Long polling не работает, пока у бота есть webhook-подписка: для локальной разработки нужен отдельный тестовый бот.
- Если MAX не может загрузить фото события, карточка отправляется без него.
- YandexGPT иногда возвращает некорректный ответ; такие события размечаются повторно при следующем обновлении.
- Отмена похода закрывает мэтч без уведомления второго участника.
