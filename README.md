# ДвижМАКС

Бот в MAX для тех, кто хочет сходить на событие, но не с кем. Показывает афишу Москвы,
а на выбранное событие — людей, которые тоже собираются пойти. Если интерес взаимный,
бот сообщает о мэтче и помогает обменяться контактами.

Бот: [@t110_hakaton_max_bot](https://max.ru/t110_hakaton_max_bot). Работает в мобильном MAX и в web.max.ru.

## Флоу пользователя

1. `/start` → согласие на обработку данных → Москва → анкета (18+) или «Только афиша».
2. Афиша: по одному событию за раз, «👍 Нравится», «Не моё» или «Хочу пойти».
3. «Хочу пойти» → «Найти компанию»: анкеты людей, которые идут на то же событие, и общие интересы.
4. «👍 Пойти вместе» — лайк. Если второй человек лайкнул в ответ, обоим приходит «Есть мэтч 🎉».
5. «Поделиться контактом» → пользователь пишет контакт → подтверждает → бот пересылает его второму.

Команды: `/start`, `/feed` (афиша), `/liked`, `/plans`, `/profile`, `/demo`.

## Архитектура

| Компонент | Что делает |
| --- | --- |
| `bot` | Принимает обновления MAX (webhook или long polling), вся логика диалога: `bot/` |
| `catalog-worker` | Раз в 12 часов забирает события из KudaGo и размечает новые через YandexGPT: `workers/catalog_worker.py` |
| `migrate` | Применяет миграции Alembic перед стартом бота и worker |
| `postgres` | Пользователи, события, реакции, планы, мэтчи, контакты |
| `redis` | Очередь подготовленных карточек ленты для каждого пользователя |
| `caddy` | Только в режиме webhook без своего nginx: HTTPS и прокси на бота |

Бот и worker не общаются напрямую — только через PostgreSQL. Все сервисы приложения
собираются из одного `Dockerfile` и отличаются командой запуска.

## Запуск

Нужны Docker с Compose v2.24+ и токен бота MAX.

```bash
git clone https://github.com/akimjlord-p/dvizhmax.git && cd dvizhmax
cp .env.example .env        # заполнить переменные из таблицы ниже
docker compose -f docker-compose.yml -f docker-compose.polling.yml up -d --build
```

Эта команда — для локальной проверки: собирает образ (около 40 секунд), применяет миграции
и запускает бота в режиме long polling, PostgreSQL, Redis и catalog-worker. Первый импорт афиши
идёт несколько минут, после него можно писать боту `/start`.

Long polling не получает сообщений, если у бота настроен webhook. Боевой бот работает
через webhook, поэтому для локального запуска нужен отдельный тестовый бот.

Другие режимы:

| Режим | Команда |
| --- | --- |
| Webhook, HTTPS через Caddy (нужен `DOMAIN` и свободные 80/443) | `docker compose -f docker-compose.yml -f docker-compose.webhook.yml up -d --build` |
| Webhook за nginx хоста (так работает прод) | `docker compose up -d --build`; конфиг сайта — `deploy/host-nginx/dvizhmax.conf` |

## Остановка и повторный запуск

```bash
docker compose down                     # остановить; данные остаются в томах
docker compose up -d                    # запустить снова
git pull && docker compose up -d --build   # обновить код; миграции применятся сами
docker compose down -v                  # удалить всё вместе с базой
```

Для режима long polling добавляйте `-f docker-compose.yml -f docker-compose.polling.yml`.

## Переменные окружения

Шаблон — `.env.example`, реальных ключей в нём нет.

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `POSTGRES_PASSWORD` | да | — | Пароль PostgreSQL |
| `DATABASE_URL` | да | — | `postgresql+psycopg://dvizhmax:<пароль>@postgres:5432/dvizhmax` |
| `MAX_BOT_TOKEN` | да | — | Токен бота MAX |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | да | — | Разметка событий. Без них новые события не попадают в ленту |
| `MAX_TRANSPORT` | нет | `webhook` | `webhook` или `long_polling` |
| `MAX_WEBHOOK_URL` | для webhook | — | Публичный HTTPS-адрес. В режиме Caddy собирается из `DOMAIN` |
| `MAX_WEBHOOK_SECRET` | для webhook | — | Секрет запросов MAX, 5–256 символов |
| `MAX_WEBHOOK_HOST` / `_PORT` / `_PATH` | нет | `0.0.0.0` / `8080` / `/max/webhook` | Где бот слушает webhook |
| `DOMAIN` | для Caddy | — | Домен бота, A-запись должна указывать на сервер |
| `REDIS_URL` | нет | — | Без него очередь ленты хранится в памяти бота |
| `YANDEX_MODEL_URI` | нет | `yandexgpt-5-lite` | Другая модель YandexGPT |
| `KUDAGO_CITIES` | нет | Москва | JSON-список городов для импорта |
| `CATALOG_REFRESH_INTERVAL_SECONDS` | нет | `43200` | Как часто обновлять афишу |
| `DEMO_TEAM_MAX_USER_IDS` | нет | — | MAX ID реальных анкет команды, которые добавляются в демо-событие |
| `PRIVACY_POLICY_VERSION` | нет | `2026-09-20` | При смене версии согласие спрашивается заново |
| `LOG_LEVEL` | нет | `INFO` | Уровень логов |

## Порты

| Порт | Кто | Доступ |
| --- | --- | --- |
| 8080 | бот, webhook | Режим с nginx хоста: только `127.0.0.1`. В остальных режимах наружу не публикуется |
| 80, 443 | Caddy | Только в режиме `docker-compose.webhook.yml` |
| 5432, 6379 | PostgreSQL, Redis | Только внутри сети Docker |

## Зависимости

Python 3.12, maxapi, SQLAlchemy 2 + psycopg 3, Alembic, httpx, redis, Yandex AI Studio SDK.
Прямые зависимости с точными версиями — `requirements.txt`, полный снимок рабочего окружения
со всеми транзитивными пакетами — `constraints.txt`.

## Внешние сервисы

| Сервис | Зачем | Что нужно | Если недоступен |
| --- | --- | --- | --- |
| MAX Bot API | Сообщения и кнопки | Токен бота; для webhook — HTTPS-адрес | Бот не отвечает |
| KudaGo API | События Москвы | Ничего, API публичный | Афиша не обновляется, показываются уже загруженные события |
| Yandex AI Studio (YandexGPT) | Теги событий для рекомендаций | API-ключ и ID каталога | Новые события не размечаются и не попадают в ленту, повтор при следующем обновлении |

Ни один из них нельзя поднять в Docker, поэтому для проверки нужен доступ в интернет и ключи.
Для проверки жюри бот уже запущен на нашем сервере — ссылка вверху.

## Данные

События загружаются из KudaGo. Бот хранит ссылку на источник и помечает событие, которое
пропало из выдачи: сначала предупреждением «Информация могла измениться», через 3 дня скрывает.
Детские события (категория «Детям» или «для детей» в названии) в ленту не попадают.

О пользователе хранится: MAX ID, город, интересы, реакции на события и планы, а с анкетой —
имя, пол, возраст, описание и фото. Поиск компании доступен только с 18 лет. Контакт
сохраняется, только если пользователь сам написал и подтвердил его после мэтча, и уходит
только второму участнику мэтча. «Мой профиль» → «🗑 Удалить профиль» удаляет пользователя
и все связанные данные. Подробнее — `docs/data_model.md`, `docs/catalog_update.md`.

Рекомендации: интерес из анкеты даёт тегу вес 1.0, «Нравится» +0.1, «Хочу пойти» +0.5,
«Не моё» 0. Событие оценивается суммой весов своих тегов, каждая четвёртая карточка случайная.

## Тестовые данные

События в афише настоящие, из KudaGo. Синтетическое только демо:

- «Демо-встреча ДвижМАКС» — отдельное событие, которого нет в афише, открывается командой `/demo`.
- «Демо Лёша», «Демо Саша», «Демо Катя» — ненастоящие анкеты с пометкой «Демо-анкета» в описании.
  У них нет аккаунтов MAX, сообщения им не отправляются.
- После них на демо-событии показываются реальные люди: анкеты команды и все, кто прошёл `/demo`.

Создать демо после первого импорта афиши: `docker compose --profile tools run --rm demo-seed`.
Сбросить: кнопка «🔄 Сбросить демо» в боте или `docker compose --profile tools run --rm demo-reset`.

## Как проверить

С одним аккаунтом, через демо:

| Шаг | Ожидаемый результат |
| --- | --- |
| `/start`, «Согласен», «Продолжить с Москвой», «Создать профиль» | Анкета: имя → пол → возраст → описание → фото → минимум 3 интереса |
| «Афиша», «👍 Нравится» на карточке | На карточке появляется «✅ Нравится», приходит следующее событие |
| `/demo` → «Хочу пойти» → «Найти компанию» | Первым показывается Демо Лёша |
| «👍 Пойти вместе» на Лёше | «Лайк отправлен. Если интерес будет взаимным — сообщим о мэтче», дальше Демо Саша |
| Смотрим Сашу | В анкете строка «Общие интересы: …» с тремя твоими интересами |
| Лайк Саше, затем лайк Демо Кате | С Катей сразу «Есть мэтч 🎉» |
| «Поделиться контактом» → написать контакт → «Да, отправить» | «Контакт отправлен», Катя отвечает своим демо-контактом |

С двумя аккаунтами: оба нажимают «Хочу пойти» и «Найти компанию» на одном событии,
первый лайкает второго. В течение минуты второму приходит «с тобой хочет пойти 1 человек»
с кнопкой «Посмотреть анкеты». Лайк в ответ — обоим «Есть мэтч 🎉», дальше обмен контактами.

## Примеры поведения

| Ситуация | Что делает бот |
| --- | --- |
| Возраст меньше 18 | «Поиск компании доступен только с 18 лет», анкета не сохраняется |
| Произвольный текст вместо кнопки | «Сейчас здесь нужно выбрать действие кнопкой ниже» и меню |
| Картинка отправлена файлом на шаге фото | Просит отправить её как фотографию или пропустить |
| MAX не смог загрузить фото события | Карточка приходит с заглушкой |
| Сбой при нажатии кнопки | «Не получилось выполнить действие… профиль и планы сохранены» + «Повторить» / «В меню» |
| Повторное нажатие на уже оценённую карточку | «Эта карточка уже оценена», дублей нет |
| Поиск компании на детском событии из старого плана | «Поиск компании недоступен для детских мероприятий» |
| Второй участник мэтча отменил поход | Поделиться контактом уже нельзя: «Этот мэтч больше не активен» |
| Сообщение о мэтче не дошло (сбой MAX или сети) | Бот повторяет отправку раз в минуту, до 10 попыток, только тому, кому не дошло |
| Неизвестная команда, например `/strat` | «Не знаю такую команду» со списком команд и меню |

## Известные ограничения

- Только Москва и только KudaGo.
- Ссылка на профиль MAX (`max://user/<id>`) не открывается, поэтому контакт пользователь пишет сам.
  Бот передаёт его дословно и не проверяет.
- Нет модерации анкет и фото, жалоб, блокировки и общего чата.
- Если отменить поход, второй участник мэтча об этом не узнает.
- Показанные без реакции карточки исключаются из ленты примерно на сутки: срок продлевается,
  пока пользователь активен. Без Redis — до перезапуска бота.
- Long polling не работает одновременно с webhook у одного бота.
- Пока бот ждёт контакт после «Поделиться контактом» (до часа), следующее сообщение считается контактом.

## Разработка

```bash
pip install -r requirements.txt -c constraints.txt
python -m unittest discover -s tests
```

Интеграционные тесты запускаются, если задан `TEST_DATABASE_URL` на отдельную базу PostgreSQL
с именем, которое заканчивается на `_test`.
