# ДвижМАКС

Бот в MAX для тех, кому не с кем сходить на событие. Выбираешь событие в Москве — видишь людей,
которые тоже собираются пойти. Если интерес взаимный, бот сообщает о мэтче и помогает
обменяться контактами.

Рабочий бот: [@t110_hakaton_max_bot](https://max.ru/t110_hakaton_max_bot) — мобильный MAX и web.max.ru.

## Быстрый старт

Нужен Docker с Compose v2.

```bash
git clone https://github.com/akimjlord-p/dvizhmax.git
cd dvizhmax
cp .env.example .env    # впишите MAX_BOT_TOKEN, YANDEX_API_KEY и YANDEX_FOLDER_ID
docker compose up -d --build
```

Через минуту напишите боту `/start`. Демо (`/demo`) готово сразу, афиша заполняется по мере
импорта из KudaGo — весь каталог Москвы загружается минут за 7.

Локально бот получает сообщения через long polling. MAX не отдаёт их так боту, у которого
настроен webhook, поэтому с токеном нашего рабочего бота локальный запуск сообщений не получит —
нужен токен отдельного бота.

```bash
docker compose ps                          # статус
docker compose logs -f bot                 # логи бота
docker compose down                        # остановить (данные сохраняются)
docker compose up -d                       # запустить снова
git pull && docker compose up -d --build   # обновить; миграции применяются сами
docker compose down -v                     # удалить вместе с данными
```

## Деплой на сервер

На сервере бот работает через webhook: MAX сам присылает обновления на HTTPS-адрес.
Нужны домен, указывающий на сервер, и nginx.

1. Допишите в `.env` (пароль базы — до первого запуска):

   ```env
   MAX_TRANSPORT=webhook
   MAX_WEBHOOK_URL=https://bot.example.com/max/webhook
   MAX_WEBHOOK_SECRET=придумайте-5-256-символов
   POSTGRES_PASSWORD=свой-пароль
   ```

2. Подключите сайт в nginx и получите сертификат:

   ```bash
   sudo cp deploy/nginx.conf /etc/nginx/sites-available/dvizhmax.conf
   sudo sed -i 's/bot.example.com/ВАШ_ДОМЕН/' /etc/nginx/sites-available/dvizhmax.conf
   sudo ln -s /etc/nginx/sites-available/dvizhmax.conf /etc/nginx/sites-enabled/
   sudo nginx -t && sudo systemctl reload nginx
   sudo certbot --nginx -d ВАШ_ДОМЕН
   ```

3. Запустите `docker compose up -d --build`. Бот сам подпишется на webhook.
   `curl -X POST https://ВАШ_ДОМЕН/max/webhook` должен вернуть 403 — запрос без секрета отклонён ботом.

## Флоу пользователя

1. `/start`: согласие на обработку данных, анкета (18+) с интересами или режим «Только афиша».
2. Афиша: по одному событию, «👍 Нравится» / «Не моё» / «Хочу пойти».
3. «Хочу пойти» → «Найти компанию»: анкеты тех, кто идёт на то же событие, и общие интересы.
4. Лайк в ответ на лайк — мэтч. После него можно поделиться контактом: бот передаст его после подтверждения.

Команды: `/start`, `/feed`, `/liked`, `/plans`, `/profile`, `/demo`.

## Как проверить

| Шаг | Ожидаемый результат |
| --- | --- |
| `/start` → «Согласен» → «Продолжить с Москвой» → «Создать профиль» | Анкета: имя, пол, возраст, описание, фото, минимум 3 интереса |
| «Афиша» → «👍 Нравится» | На карточке «✅ Нравится», приходит следующее событие |
| `/demo` → «Хочу пойти» → «Найти компанию» | Первой показывается анкета Демо Лёши |
| «👍 Пойти вместе» на Лёше | «Лайк отправлен. Если интерес будет взаимным — сообщим о мэтче», затем Демо Саша |
| Анкета Саши | Строка «Общие интересы: …» |
| Лайк Саше, затем Демо Кате | С Катей сразу «Есть мэтч 🎉» |
| «Поделиться контактом» → написать контакт → «Да, отправить» | «Контакт отправлен», Катя отвечает своим демо-контактом |

С двумя аккаунтами: оба выбирают одно событие и «Найти компанию», первый лайкает второго.
Второму в течение минуты приходит «с тобой хочет пойти 1 человек» с кнопкой «Посмотреть анкеты».
Ответный лайк — обоим «Есть мэтч 🎉».

## Примеры поведения

| Ситуация | Что делает бот |
| --- | --- |
| Возраст меньше 18 | «Поиск компании доступен только с 18 лет», возраст не сохраняется |
| Текст вместо кнопки | «Сейчас здесь нужно выбрать действие кнопкой ниже» и меню |
| Неизвестная команда | «Не знаю такую команду» и список команд |
| Картинка отправлена файлом на шаге фото | Просит отправить её как фотографию или пропустить |
| MAX не смог загрузить фото события | Карточка приходит с заглушкой |
| Сбой при нажатии кнопки | «Не получилось выполнить действие… профиль и планы сохранены», «Повторить» / «В меню» |
| Повторное нажатие на оценённую карточку | «Эта карточка уже оценена», дублей нет |
| Сообщение о мэтче не дошло | Повтор раз в минуту, до 10 попыток, только тому, кому не дошло |

## Архитектура

| Компонент | Что делает |
| --- | --- |
| `bot` | Диалог с пользователем в MAX: `bot/` |
| `catalog-worker` | Раз в 12 часов загружает события KudaGo, размечает новые через YandexGPT, обновляет демо: `workers/catalog_worker.py` |
| `migrate` | Применяет миграции Alembic перед стартом бота и воркера |
| `postgres` | Пользователи, события, реакции, планы, мэтчи, контакты |
| `redis` | Очередь подготовленных карточек ленты |

Бот и воркер обмениваются данными только через PostgreSQL. Все три сервиса приложения
собираются из одного `Dockerfile`. Схема данных — `docs/data_model.md`, импорт — `docs/catalog_update.md`.

## Переменные окружения

Шаблон — `.env.example`. Адреса PostgreSQL и Redis `docker-compose.yml` задаёт сам.

| Переменная | Нужна | По умолчанию | Зачем |
| --- | --- | --- | --- |
| `MAX_BOT_TOKEN` | да | — | Токен бота MAX |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | да | — | Разметка событий YandexGPT; без неё новые события не попадают в ленту |
| `MAX_TRANSPORT` | нет | `long_polling` | `webhook` на сервере |
| `MAX_WEBHOOK_URL`, `MAX_WEBHOOK_SECRET` | для webhook | — | HTTPS-адрес webhook и секрет запросов MAX |
| `POSTGRES_PASSWORD` | нет | `dvizhmax` | Пароль базы; на сервере задайте свой |
| `DEMO_TEAM_MAX_USER_IDS` | нет | — | MAX ID реальных анкет команды, которые добавляются в демо |
| `KUDAGO_CITIES` | нет | Москва | Города для импорта, JSON |
| `CATALOG_REFRESH_INTERVAL_SECONDS` | нет | `43200` | Как часто обновлять афишу |
| `LOG_LEVEL` | нет | `INFO` | Уровень логов |

## Порты

| Порт | Сервис | Доступ |
| --- | --- | --- |
| 8080 | `bot`, webhook | Только `127.0.0.1` — для nginx на том же сервере; в long polling не используется |
| 5432, 6379 | PostgreSQL, Redis | Только внутри сети Docker |

## Зависимости

Python 3.12, maxapi, SQLAlchemy 2 + psycopg 3, Alembic, httpx, redis, Yandex AI Studio SDK.
Точные версии прямых зависимостей — `requirements.txt`, полный снимок окружения — `constraints.txt`.

## Внешние сервисы

| Сервис | Зачем | Что нужно | Если недоступен |
| --- | --- | --- | --- |
| MAX Bot API | Сообщения и кнопки | Токен бота | Бот не отвечает |
| KudaGo API | События Москвы | Ничего, API открытый | Афиша не обновляется, остаются загруженные события |
| Yandex AI Studio | Теги событий для рекомендаций | API-ключ и ID каталога | Новые события не попадают в ленту до следующего обновления |

Ни один из них не запускается в Docker: для работы нужны интернет и ключи.

## Данные

События — из KudaGo. Если событие пропало из выдачи, карточка получает предупреждение
«Информация могла измениться», через 3 дня скрывается. Детские события (категория «Детям»
или «для детей» в названии) в ленту не попадают.

О пользователе хранятся MAX ID, город, интересы, реакции и планы, с анкетой — имя, пол,
возраст, описание и фото. Контакт сохраняется, только если пользователь сам написал и подтвердил
его после мэтча, и уходит только второму участнику мэтча. «Мой профиль» → «🗑 Удалить профиль»
удаляет пользователя со всеми данными.

Рекомендации: интерес из анкеты даёт тегу вес 1.0, «Нравится» +0.1, «Хочу пойти» +0.5,
«Не моё» 0. Событие оценивается суммой весов тегов, каждая четвёртая карточка случайная.

## Тестовые данные

События в афише настоящие. Синтетическое только демо, оно создаётся автоматически:

- «Демо-встреча ДвижМАКС» — событие, которого нет в афише; открывается командой `/demo`.
- «Демо Лёша», «Демо Саша», «Демо Катя» — ненастоящие анкеты с пометкой «Демо-анкета»,
  сообщения им не отправляются. После них показываются живые участники демо-события.
- «🔄 Сбросить демо» в боте начинает сценарий заново. Полный сброс демо-события для всех:
  `docker compose run --rm demo-reset`.

## Известные ограничения

- Только Москва и только KudaGo.
- Ссылка на профиль MAX не открывается, поэтому контакт пользователь пишет сам. Бот передаёт
  его дословно и не проверяет.
- Нет модерации анкет и фото, жалоб, блокировки и общего чата.
- Если отменить поход, второй участник мэтча об этом не узнает.
- Показанные без реакции карточки не возвращаются в ленту примерно сутки, пока пользователь активен.
- Пока бот ждёт контакт (до часа), следующее сообщение считается контактом.

## Разработка

```bash
pip install -r requirements.txt -c constraints.txt
python -m unittest discover -s tests
```

Для интеграционных тестов нужна отдельная база PostgreSQL с именем на `_test`:
`TEST_DATABASE_URL=postgresql+psycopg://…/dvizhmax_test`.
