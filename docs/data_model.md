# Схема данных

Модели находятся в `infrastructure/db/models.py` и
`infrastructure/db/social_models.py`. Миграции — в `infrastructure/db/migrations`.

## Каталог

| Таблица | Назначение |
| --- | --- |
| `cities` | Город, часовой пояс и код источника. |
| `events` | Общая карточка события: текст, цена, возрастной порог, статусы данных и разметки. |
| `event_sources` | Внешний ID, ссылка, исходный JSON и время проверки. |
| `places` | Площадка и координаты. |
| `event_images` | Фотографии источника. |
| `event_schedules` | Расписания источника. |
| `tags` | Фиксированный словарь тегов. |
| `event_tags` | Связь события с тегами. |
| `import_runs` | Результат одного импорта по городу. |

`event_sources(source, external_id)` уникальна. Для события допускается один
основной источник. `event_tags` хранит до двух первичных тегов по правилу
валидатора YandexTagger.

## Пользователь и рекомендации

| Таблица | Назначение |
| --- | --- |
| `users` | MAX ID, город, анкета, состояние онбординга. |
| `user_consents` | Принятая версия согласия. |
| `user_tag_weights` | Стартовый и накопленный вес каждого тега пользователя. |
| `event_reactions` | Одна реакция пользователя на событие: `like` или `skip`. |
| `event_plans` | Один план пользователя на событие: `planned`, `cancelled` или `completed`. |

У активной анкеты обязательны имя, пол, возраст и город. Фото и описание
необязательны. Вес рекомендации равен сумме веса тегов: у первичных множитель
`1.0`, у вторичных — `0.4`.

## Поиск компании

| Таблица | Назначение |
| --- | --- |
| `companion_views` | Кого пользователь уже видел по конкретному событию и когда отреагировал. |
| `companion_interests` | Направленный лайк между двумя планами одного события. |
| `matches` | Взаимный лайк пары пользователей по событию. |
| `user_blocks` | Направленная блокировка пользователя. |
| `notifications` | Запас таблицы для будущей очереди уведомлений; в MVP не используется. |
| `notification_interests` | Состав будущей сводки очереди уведомлений; в MVP не используется. |

Ключ `companion_views(viewer_id, event_id, shown_user_id)` исключает повторный
показ одного человека в рамках события. `matches` уникальна по событию и
отсортированной паре пользователей.

`companion_interests.announced_at` отмечает односторонний интерес, о котором
бот уже сообщил адресату в ежеминутной сводке. Взаимный интерес создаёт запись
в `matches` и отправляет уведомление сразу, без очереди.
