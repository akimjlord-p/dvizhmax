# Обновление карточек

`workers.catalog_worker` запускается отдельно от бота. После старта он обновляет
каждый город из `KUDAGO_CITIES`, затем повторяет цикл с интервалом
`CATALOG_REFRESH_INTERVAL_SECONDS` (по умолчанию 12 часов).

```text
KudaGo → normalize_event → CatalogRepository.upsert_event → PostgreSQL
                                              ↓
                                  YandexTagger для pending / failed
                                              ↓
                                         EventTag
```

Для каждого города worker:

1. Создаёт или находит `City` по коду KudaGo и добавляет отсутствующие теги словаря.
2. Создаёт `ImportRun` со статусом `running`.
3. Получает карточки KudaGo постранично. Каждая карточка нормализуется и сохраняется
   в отдельной транзакции.
4. Новое событие сохраняется с `tagging_status=pending`, затем отправляется в
   Yandex AI Studio. При успешном ответе создаются `EventTag` и статус становится
   `done`; при ошибке — `failed`.
5. Обновляет `ImportRun` счётчиками созданных и обновлённых карточек.

Ключ события — пара `source + external_id` в `event_sources`.
При повторной загрузке обновляются город, площадка, цена, бесплатность, возрастной
порог, ссылка источника, исходный JSON, фотографии и расписание. Название, описание
и уже назначенные теги не меняются. Фотографии и расписание источника заменяются
целиком актуальной версией.

Карточка доступна ленте, когда `data_status` равен `current` или `uncertain`, а
`tagging_status=done`, у него есть актуальный сеанс и возрастной порог не выше
возраста пользователя.

Статусы актуальности:

- `current` — событие получено в последнем обновлении.
- `uncertain` — обновление города завершилось успешно, но события в выдаче KudaGo не было.
  Карточка остаётся в ленте с предупреждением «⚠️ Информация могла измениться».
- `unavailable` — источник не подтверждал событие больше 3 дней (`SOURCE_STALE_AFTER`).
  Карточка больше не показывается в ленте и в «Понравившихся», но остаётся в «Моих планах».

Если обновление города упало, события не помечаются `uncertain`, чтобы сбой KudaGo
не испортил каталог. Событие, снова появившееся в выдаче, возвращается в `current`.
Разметка, завершившаяся ошибкой (`failed`), повторяется при следующем обновлении.

ИИ использует фиксированный словарь из `integrations/yandex_tagger.py`: от одного
до двух первичных и любое число вторичных тегов. Цена, дата, место и возрастной
порог остаются полями события, а не тегами.

## Изображения в ленте

Бот берёт первую фотографию из `event_images`. Если у события нет фотографии,
используется `assets/images/event-no-image.jpg`. Для фотографии KudaGo в MAX
передаётся исходный URL: бот не скачивает изображение и не загружает его заново.
Это сокращает задержку при смене карточки. Если MAX не может загрузить фото по URL
(`Failed to upload image`), бот сразу отправляет ту же карточку с заглушкой.
