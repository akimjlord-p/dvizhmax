# Пользовательский flow

```text
/start
  → согласие на обработку данных
  → город
  → создать профиль или продолжить как гость

Гость
  → /feed → Нравится / Не интересно / Пойду
  → Пойду → планы → запрос поиска компании
  → создать профиль при необходимости

Профиль
  → имя → пол → возраст → описание (опционально) → фото (опционально) → интересы
  → /feed
```

## События

В `/feed` показывается одно непросмотренное событие. `Нравится` сохраняет реакцию
`like` и добавляет `+0.1` к каждому тегу события. `Не интересно` сохраняет `skip`
без изменения весов. После любой реакции карточка больше не появляется в ленте.

`Пойду` создаёт план и даёт суммарный вклад `+0.5` к тегам события. Поэтому после
предварительного лайка добавляется ещё `+0.4`; прямое нажатие `Пойду` сохраняет
лайк и сразу даёт `+0.5`.

`/liked` показывает понравившиеся события без активного плана. В `/plans` есть
активные планы. В обоих разделах карточки листаются inline-кнопками. Лайк можно
снять: событие остаётся скрытым из ленты. План можно отменить: поиск компании
выключается, связанные интересы отзываются, а матчи закрываются.

## Поиск компании

После `Пойду` бот спрашивает, нужно ли искать компанию. Поиск доступен только
пользователю с активной анкетой. Если анкеты нет, бот предлагает её создать;
сохранённые планы и веса остаются.

При включённом поиске показываются пользователи, которые тоже имеют активный план
на это событие и сами ищут компанию. Исключаются собственная анкета, блокировки в
обе стороны и уже показанные пользователи. Показ сохраняется до отправки карточки;
если отправка в MAX завершается ошибкой, транзакция откатывается.

Лайк создаёт направленный `companion_interest`. Два встречных активных лайка
создают `match`. Сейчас бот показывает сообщение о мэтче; отправка контактов и
создание общего чата ещё не реализованы.
